## 2. Задача: агент по промптам

**Смысл**: пользователь пишет поверхностно («злой робот в дождливом городе, крупный план»),
агент возвращает готовый промпт **в формате конкретной модели** + её параметры.

**Решения владельца (17.11):**

- агент нужен **и для картинок, и для видео** (генерация анимации) — обязательно в обоих местах;
- агент **обязан видеть картинки**: сценарий «скинул персонажа → возьми его стиль →
  напиши промпт для нового персонажа такого-то»;
- значит `llama-server` запускается всегда с `--mmproj` (Gemma 4 мультимодальная),
  и в запросе к агенту картинка передаётся как изображение, а не как описание.

**Что уже есть на машине (найдено 17.11)**

| Компонент | Путь / порт | Примечание |
|---|---|---|
| llama.cpp (server + dll) | `E:\ComfyModelsHub\models\MinimaxH3_assistant\llama.cpp\llama-server.exe` | полный набор утилит, ничего скачивать не нужно (перенесено с F: на SSD 18.11) |
| Модель ассистента | `…\models\gemma-4-12B-it-Q4_0.gguf` (6.7 ГБ) | Gemma 4 12B, Q4_0 |
| Мультимодальный проектор | `…\models\mmproj-gemma-4-12B-it-Q8_0.gguf` | видит картинки (пригодится: «сделай промпт по этому персонажу») |
| Референсный агент | `http://127.0.0.1:8280` (сейчас запущен приложением Minimax H3) | в его логе: контекст 49152, 14 потоков |

**План**

1. Свой экземпляр `llama-server` на **8281** (не мешать референсному 8280), контекст 16–24k,
   `--mmproj` для картинок. Запуск из студии по требованию + keepalive + стоп при выходе
   (как сделано для редактора на 8091).
2. `GET /api/agent/status` (модель, порт, готовность), `POST /api/agent/prompt`
   `{model, brief, image?}` → `{prompt, negative, steps, cfg, size, skill}`.
3. Скиллы (см. раздел 3) кладутся в system-сообщение; в ответе показываем, какой скилл сработал.
4. UI: кнопка **«✨ Промпт агентом»** рядом с полем промпта в каждой вкладке; черновик
   показывается до вставки («вставить» / «ещё вариант»). Если агент не запущен — кнопка
   объясняет, чего не хватает, а не молчит.
5. Проверка: по 3 брифам на 3 модели — промпт проходит лимиты модели и даёт нормальный
   результат при генерации.

**Ограничения**: только локально, без интернета. 12B на Q4 делит память с ComfyUI —
замерять первый ответ и решить, выгружать ли модели ComfyUI перед агентом.

## 6. Риски

- **Память**: ComfyUI держит 20–30 ГБ моделей; Gemma 12B Q4 — ещё ~7 ГБ, а с `--mmproj`
  и картинкой в запросе расход выше. Возможен своп. Решение: запускать агента по требованию,
  ограничивать контекст, мерить первый ответ с картинкой и без.
- **Шаблоны ComfyUI**: ноды 2.1 новые (`QwenImage21Cache`, `TextEncodeQwenImage21`),
  вложенные поля обязательны — валидация `/prompt` сразу покажет, что забыли.
- **Скиллы**: длинные (до 28 КБ); в контекст 16k войдёт один скилл + references по частям,
  поэтому — только нужный скилл, остальное по запросу.
- **Совместимость**: наши воркфлоу и редактор не должны зависеть от агента — он
  необязательный слой, без него всё работает как сейчас.
